## The design (exact, minimal)

### 1. Register a `workstate` adapter — generic mechanics only
- `adapters.ts`: add a second key `'workstate'` to the `draftAdapters` record — `stage` delegates to the new module below; `project(projection, writes)` returns the projection unchanged (zero writes to fold in); no `checkRequest` (fidelity needs deps the checkRequest signature doesn't carry).
- `config/drafting/adapters.yaml`: add `workstate: {domain: workstate, operations: [compose-workstate], projection: {}}` (the YAML `projection{}` map is intent-echo; the session document lives in `result` — see 3).
- **`FormDraftService.ts` and `draftRoutes.ts` expect ZERO changes.** `stage()` receives the full `AppContext` as its `context` parameter, so the workstate adapter builds its own deps — no constructor plumbing, and critically NO adapter-name branch may be added to the service (its generic gates — operations membership, canAccept, reviewHash, actor — are exactly what make this generic). If the worker finds a real gap, the smallest generic change goes in the report with justification.

### 2. New module — `server/src/drafts/workstateCompile.ts` (+ `workstateCompile.test.ts`)
```ts
export interface WorkstateDeps { resolveSpine: ActionSpineLike; surfaces: SurfacesRegistry; store: RecordStore; validate: (doc: unknown, id: string) => ValidationResult; }
export function workstateDepsFromContext(ctx: AppContext): WorkstateDeps;   // spine via createResolveSpineFromContext({...ctx, getAppConfig:()=>ctx.appConfig}); surfaces via loadDefaultSurfacesRegistry(ctx.schemaDir); validation via ctx.validator
export async function compileWorkstateIntent(intent: Record<string, unknown>, deps: WorkstateDeps): Promise<{ ok: true; result: WorkstateCompileResult } | { ok: false; diagnostics: Array<{ path: string; message: string }> }>;
export interface WorkstateCompileResult { sessionDocument: SessionDocument; summary: string; resolvedTerms: Array<{ term: string; curieOrRecordId: string; label: string }>; }
```
`sessionDocument` is the plain `{version: 1, tabs: [...], activeTabId}` transport shape (a local structural type in this module; the lab-session `$id` is the authority, this is typing convenience).
Compile steps — EACH failure returns a `path`-named diagnostic, and the adapter's `stage()` throws `DraftError(diagnostics.map(d=>`${d.path}: ${d.message}`).join('; '))`, exactly the sequence-fidelity pattern (`FormDraftService.ts:111-112`), which the pipeline converts to a `needs-missing-fact` diagnostic + `canAccept:false`. NOTHING is written at any step:
1. **Envelope**: Ajv-validate the intent (AFTER the compiler injects `requestId` — `FormDraftService.ts:106` — so the schema must declare `requestId`) against the NEW registered schema `$id` (step 3) via the Ajv-through-SchemaRegistry pattern (`ai/protocolEditValidation.ts` precedent: lazy singleton, load failure = validation failure, never silence). Fail ⇒ `MALFORMED_ENVELOPE` naming the offending path.
2. **Per-tab resolution**: each proposed tab `{surface, target}`: `deps.surfaces.get(surface)` null ⇒ `UNSUPPORTED_SURFACE` (registry membership only — repo rule #1/#3). Target `{term}` ⇒ spine `resolve(term,{localOnly:true})`, EXCLUDE mint (`tier===5 || source==='mint' || !curie`), bind tiers [0,1] — import the guards from PB-CH-1 (4). Zero candidates ⇒ `UNRESOLVED_TERM <term>`. Target `{recordId}` ⇒ `store.get` must hit or `UNKNOWN_RECORD` (invented ids never project). The resolved record's `kind` maps to a tab via the DECLARATIVE mapping (5); kinds with no mapping ⇒ `UNMAPPABLE_RECORD_KIND` diagnostic — never a TS if-chain on kind names.
3. **activeTabId**: the intent's activeTab selects one PROPOSED tab (by index or by the same target shape); the server derives the id via the mapping's `idPrefix` (`run:<runId>`, `project:<studyId>`, `record:<recordId>` — the tabId.ts conventions cited above, mirrored in YAML data, not in code); no activeTab ⇒ `null` (schema-legal). An activeTab target that isn't among the tabs or doesn't resolve ⇒ `ACTIVE_TAB_UNRESOLVED`; an id never referencing a projected tab is UNSTRUCTURALLY IMPOSSIBLE because the server mints it, never the client.
4. **Project + re-validate**: build `{version: 1, tabs, activeTabId}` and Ajv-validate against the REGISTERED `workflow/lab-session.schema.yaml` `$id` (already boot-registered by the schema glob — no registration change). A projection failing re-validation is `COMPILE_INTERNAL`, surfaced as diagnostics, never emitted.
`stage()` returns `{...result}` as `compiled.result` with ZERO staged creates.
