# Biology Engine Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Evolve the existing compiler + resolve spine + clarification loop into a layered biology engine that separates biological semantics, laboratory state, operational semantics, and execution binding — with a typed intent graph as the intermediate representation.

**Architecture:** The system already contains most of the machinery: a shared resolve spine, a deterministic clarification net, a ProtocolIntent intermediate representation, and a 28-pass compiler pipeline. The work is to CONNECT and GENERALIZE these pieces: unify the three verb normalization maps, generalize forceMaterialClarifications into a multi-gap-type engine, wire ProtocolIntent into the AI agent's draft flow, and add graph patching to replace full re-drafts.

**Tech Stack:** TypeScript, Fastify, React, Zod, vitest, vLLM (Qwen3.6-27B)

---

## Current State vs. Proposed Architecture

### What Already Exists (from the three reports)

1. **Resolve spine** (POST /resolve) — 5-tier: local records → OAK → OLS4 → vendor → mint. Used by combobox, AI agent, compiler.
2. **forceMaterialClarifications** — deterministic net detecting 3 gap types: no-ref, unverified-curie, needs-quantity. Holds whole draft, returns clarification cards.
3. **BiologyVerbExpander** — 26 expanders lowering verbs to 9 primitive event types. 3 independent normalization maps.
4. **ProtocolIntent** — a typed intermediate representation with resources (labware, materials, formulations, aliquots, pipettes), operations, patterns, assumptions, and unresolved facts. Has resolutionStatus per entity. BUT: only used in deterministic precompile path, NOT in AI agent draft flow.
5. **ProtocolCompiler** — separate instrument binding via EquipmentCapabilityService. Disconnected from chatbot-compile.
6. **ExecutionScalePlan** — infers equipment classes from prompt cues. Does not bind specific instruments.

### What's Missing (from biology-engine.md)

1. **ProtocolIntent not wired to AI agent** — the LLM drafts events directly via compile_event_graph_draft tool, bypassing ProtocolIntent
2. **No unified operation registry** — three disconnected verb normalization maps, no canonical operation set
3. **Only 3 gap types** — no capability gap, no instance gap, no semantic conflict gap
4. **Full re-draft on every clarification** — no graph patching, stable IDs can change
5. **No SemanticBinding type** — resolve spine returns candidates, not rich binding objects with evidence
6. **Compile and execution layers disconnected** — verb expanders and ProtocolCompiler don't share vocabulary
7. **No "shake" verb** — missing from all normalization maps and expanders

---

## Phased Implementation

### Phase 1: Unified Operation Registry (Foundation)

Unify the three verb normalization maps into a single YAML-driven registry. Add missing operations (agitate, control_temperature, etc.) as aliases for existing primitive event types.

### Phase 2: Generalized Semantic Gap Engine

Extend forceMaterialClarifications into a multi-gap-type engine supporting identity, instance, parameter, capability, and semantic conflict gaps.

### Phase 3: ProtocolIntent as AI Draft Intermediate

Wire ProtocolIntent into the AI agent's draft flow so the LLM produces intent graphs instead of directly drafting events.

### Phase 4: Graph Patching

Replace full re-draft-after-every-clarification with deterministic graph patches.

### Phase 5: Execution Binding Bridge

Connect the chatbot-compile pipeline's operation requirements to the ProtocolCompiler's instrument capability matching.

```typescript
import { z } from 'zod';
import { resolve, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';
import { readFileSync } from 'node:fs';
import { parse as parseYaml } from 'yaml';

const OperationSchema = z.object({
  id: z.string(),
  label: z.string(),
  primitive: z.string().nullable(),
  expands_to: z.array(z.string()).optional(),
  aliases: z.array(z.string()).default([]),
  ontology_refs: z.array(z.object({
    source: z.string(),
    id: z.string(),
  })).optional(),
  notes: z.string().optional(),
});

const OperationRegistrySchema = z.object({
  kind: z.literal('operation-registry'),
  version: z.string(),
  operations: z.array(OperationSchema),
});

export type Operation = z.infer<typeof OperationSchema>;

export class OperationRegistry {
  private readonly operations: Map<string, Operation>;
  private readonly aliasIndex: Map<string, string>;

  constructor(data: z.infer<typeof OperationRegistrySchema>) {
    this.operations = new Map();
    this.aliasIndex = new Map();
    for (const op of data.operations) {
      this.operations.set(op.id, op);
      this.aliasIndex.set(op.id, op.id);
      for (const alias of op.aliases) {
        this.aliasIndex.set(alias.toLowerCase(), op.id);
      }
    }
  }

  lookup(verb: string): Operation | undefined {
    const canonical = this.aliasIndex.get(verb.toLowerCase());
    if (!canonical) return undefined;
    return this.operations.get(canonical);
  }

  listPrimitives(): Operation[] {
    return [...this.operations.values()].filter((op) => op.primitive !== null);
  }

  listAll(): Operation[] {
    return [...this.operations.values()];
  }
}

const YAML_PATH = resolve(
  dirname(fileURLToPath(import.meta.url)),
  '../../../schema/registry/operations.yaml',
);

let _cached: OperationRegistry | null = null;

export function getOperationRegistry(): OperationRegistry {
  if (!_cached) {
    const raw = readFileSync(YAML_PATH, 'utf8');
    const parsed = OperationRegistrySchema.parse(parseYaml(raw));
    _cached = new OperationRegistry(parsed);
  }
  return _cached;
}
```

  | 'no-ref'              // identity gap: no material reference

// In classifyEvent, after the trusted check:
// If material is a concept (material_ref with kind 'ontology' or 'record')
// but the lab's inventory has no material-instance or aliquot for it,
// surface an instance-gap.

function hasInstanceGap(details: Dict, resolved: Set<string>): boolean {
  // Check if the material has any inventory backing
  // This requires store access — for now, flag concepts without
  // material_instance_ref or aliquot_ref as potential instance gaps
  // only when materialTracking mode is 'tracked'
  if (hasTrustedSpecOrAliquot(details)) return false;
  const mr = details.material_ref;
  if (!mr) return false;
  // In tracked mode, a concept without an instance is a gap
  return !details.material_instance_ref && !details.aliquot_ref;
}

export function createCheckInstrumentCapabilitiesPass(): Pass {
  return {
    id: 'check_instrument_capabilities',
    family: 'validate',
    run({ state }: PassRunArgs): PassResult {
      const events = getEventsFromState(state);
      const instruments = getInstrumentRegistry().list();
      const diagnostics: PassDiagnostic[] = [];

      for (const event of events) {
        const requirements = inferOperationRequirements(event);
        if (!requirements) continue;
        const capable = instruments.some((inst) =>
          instrumentSupports(inst, requirements),
        );
        if (!capable) {
          diagnostics.push({
            pass_id: 'check_instrument_capabilities',
            severity: 'warning',
            code: 'no_instrument_capability',
            message: `No registered instrument can perform ${requirements.operation}` +
              (requirements.constraints
                ? ` with constraints: ${JSON.stringify(requirements.constraints)}`
                : ''),
          });
        }
      }

      return { ok: true, output: {}, diagnostics };
    },
  };
}

## Risks and Tradeoffs

1. **ProtocolIntent is already partially built** — The existing ProtocolIntent types and lowering passes are used in the deterministic precompile path. Wiring them into the AI agent flow may require changes to the pipeline ordering and the tool schema. Risk: breaking existing deterministic-only mode.

2. **Graph patching vs. re-draft** — Patching is more stable but harder to implement correctly. The current full-re-draft approach is simple and handles edge cases (like changing "incubate" to "centrifuge") naturally. Trade-off: start with patching for simple cases (bind_entity, set_parameter), fall back to re-draft for structural changes.

3. **Operation registry migration** — Replacing three normalization maps with one YAML is a refactor that touches the compiler, foundry, and AI agent. Risk: subtle behavior changes in verb normalization. Mitigation: run all existing tests after migration.

4. **Capability gap detection** — Requires instrument capability data that may not exist for all operations. Start with warnings, not blocks.

5. **LLM model capability** — The Qwen3.6-27B model may struggle to produce well-structured intent graphs. Risk: the model produces malformed intent. Mitigation: the deterministic engine normalizes and validates, falling back to direct event drafting if intent parsing fails.
