## ADDENDUM 2 — lane tooling repair: `cl-reconcile.sh` no longer dies mid-digest (07:24 EST)

`cl-reconcile.sh 2` timed out at 120 s on this tick's FIRST call, after printing the worktree section and
before the stack section (exit 124). Root cause measured, not guessed: the worktree loop ran an unbounded
`git status --porcelain` per worktree at `timeout 20`, and on this NFS checkout each call costs ~20 s — so a
long lane worktree list alone ate the caller's entire budget. A second defect hid inside it: the status count was
piped through `wc -l`, so a KILLED git still produced `dirty=0`, i.e. a timed-out worktree was silently reported
as CLEAN — the one thing a reconciliation digest must never do.

Fix (read-only tooling, same file, no behaviour change to any other section): bound the status call at 6 s,
capture its exit code, and print `dirty=?timeout` when it is killed instead of `0`. Re-ran it end-to-end:
**wall time 42 s, exit 0, all sections present** —
