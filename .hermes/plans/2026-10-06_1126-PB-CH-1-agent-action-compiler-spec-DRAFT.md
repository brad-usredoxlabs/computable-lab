## The design (exact, minimal)

### New module — the focused compiler (the task's "focused compiler module")
`server/src/ai/compileWorkspaceAction.ts` (+ `compileWorkspaceAction.test.ts`):
```ts
export interface WorkspaceActionCompilerDeps {
  resolveSpine: ResolveSpine;          // reuse, never re-implement (resolve/index.ts exports)
  surfaces: SurfacesRegistry;          // reuse server/src/surfaces/surfaces.ts
  store: RecordStore;                  // existence checks for record targets + protocol steps
}
export type CompileResult =
  | { ok: true; action: ResolvedAgentAction }                       // Ajv-valid, refs real
  | { ok: false; diagnostics: Array<{ code: WorkspaceActionDiagnosticCode; message: string; term?: string }> };
export async function compileWorkspaceAction(proposal: unknown, deps: WorkspaceActionCompilerDeps): Promise<CompileResult>;
```
Compile steps, in order — EACH failure is a diagnostic, not an action, and compilation stops there:
1. **Envelope**: Ajv-validate the raw proposal against the REGISTERED agent-action `$id` (build the validator through SchemaLoader -> SchemaRegistry -> AjvValidator exactly like `server/src/ai/protocolEditValidation.ts` does for the protocol-edit envelope — lazy singleton, candidate schema roots, load failure = validation failure with cause, never silence). Fail => diagnostic `MALFORMED_ENVELOPE` (Ajv errors formatted, offending path named).
2. **Surface check (open-surface)**: `deps.surfaces.get(surface)`; null => `UNSUPPORTED_SURFACE`. NO TS allow-list — registry membership only.
3. **Target resolution**:
   - `target.kind === 'protocol-step'`: `store.get(protocolId)`; missing => `UNKNOWN_RECORD`; `stepId` not in payload `steps[].stepId` => `UNKNOWN_STEP`. Resolved label = the record's step label (authoritative; `contextNote` may only annotate).
   - record/ontology target: if `kind:'record'` -> `store.get(id)`; missing => `UNKNOWN_RECORD` (an invented record id NEVER passes — this is the "invented record id rejected" criterion; the model does not get to name records it invented). If the target carries a TERM (the model proposes terms: a label/term with no verifiable id, or an ontology term as text) -> `resolveSpine.resolve(term, { localOnly: true })`; filter OUT tier-5/mint candidates; keep LOCAL tiers [0,1] per the resolveDraftMaterials precedent. Zero candidates => `UNRESOLVED_TERM`. Ambiguity rule (MINIMAL, deterministic — see open question 1): if two+ candidates at the SAME top tier both score exactly at the top (both label-exact after spine's own matchBonus), that is `AMBIGUOUS_TERM` naming the term and the candidate labels. Otherwise bind the top candidate: record curie `local:<recordId>` -> `{kind:'record', type:<record kind>, id:<recordId>, label:<resolved label>}`; canonical CURIE -> `{kind:'ontology', id:<CURIE>, ...}` from the candidate fields.
4. **Rewrite + re-validate**: build the resolved action (server overwrites `target.label` with the authoritative resolved label; strips anything the schema forbids — it re-validates anyway) and Ajv-validate the RESOLVED action against the same `$id`. A resolved action failing re-validation is a server bug surfaced as `COMPILE_INTERNAL`, never emitted.
Emit ONLY `ok:true` results as `agent_action`; `ok:false` emits `pipeline_diagnostics` (existing channel, client already renders it as trace lines, useChatThread.ts:186-190) with `pass_id: 'workspace-action-compile'` and the structured diagnostics. NO new error event, NO new channel.
