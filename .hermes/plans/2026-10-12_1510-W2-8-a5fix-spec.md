In IntentCompileFromPromptHandlers.ts, when `answers` is non-empty, compose the
compileFromSmallLlm prompt with the answers as EXPLICIT scientist-stated choices —
e.g. append a "Scientist-resolved choices: axisId = value" block built from the body

RED-first handler test: answered request capture passed to compileFromSmallLlm contains
every answers entry (mock client, capture prompt); unanswered capture lacks the block.

### C — client: fold the held bundle instead of discarding it (OQ4(a) as designed)

carries error==='NEEDS_CLARIFICATION' WITH localMacro && terminalArtifacts, fold it

held macro, or any other failure, keeps the current error path. apiClient:
intentCompileFromPrompt must expose the 422 body (ApiError carries parsed body — verify

The Accept leg (intentAccept with answers -> branch_resolution, server UNCHANGED —
