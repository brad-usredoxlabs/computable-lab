## Design decisions

**D1 — Truthful terminal stage (task (1)).** In `extractProtocolStream`, after the loop (:836), before merge/done:
- `chunkResults.length === 0` (zero parsed on a text-bearing source — the handler already 400s empty text at :722–725, so every reaching run is text-bearing): emit `{type:'stage', index: currentIndex, total: chunks.length, message:'Extraction failed: no parseable candidate in N chunk(s)'}` (N = chunks.length), then `{type:'error', message:'Extraction failed: no parseable candidate in N chunk(s) — every chunk produced reasoning or text without a parseable JSON candidate; see the raw-tail previews above.'}`, `request.log.warn` the same, and return WITHOUT `done`. `mergeChunkResults`'s zero-chunk empty-success object (:515–522) may still be used by the blocking legacy path — leave it (out of scope, §stop); the stream simply never reaches it.
- Zero-STEP merge (parsed candidates exist but merged steps are empty — e.g. every chunk returned `steps: []`) on this text-bearing route is ALSO a failure per the task block: same FAILED/error treatment (detect post-merge, still before persist/done — this is the case VPDF-3's seam says it deliberately leaves to me).
- PARTIAL (1 ≤ parsed < chunks.length): do NOT fail. Before `done`, emit a coverage `stage` event: `Parsed P of M chunks` (P = chunkResults.length, M = chunks.length), and push one merged-candidate diagnostic `{severity:'warning', code:'PARTIAL_CHUNK_COVERAGE', message:'Parsed P of M chunks — Q chunk(s) produced no JSON and contributed no steps'}`. Diagnostics concatenate for free at :571–583. The client renders stage + candidate diagnostics it already renders; **`done`'s shape gains nothing from me** (seam).
- Client: `case 'done'` (:636–640) keeps setting 'Extraction complete' — truthful now, because the server only sends `done` for genuinely parsed runs. One client-side belt (task (1) "never 'Extraction complete'"): in `case 'done'`, if `candidate.steps` is empty, paint 'Extraction failed: candidate has zero steps' instead — cheap, testable, no server dependency.
