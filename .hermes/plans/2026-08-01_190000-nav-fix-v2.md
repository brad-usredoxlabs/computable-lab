# Navigation Fix Plan v2 — True Browser Tabs

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Fix the three regressions from the first navigation pass and realign with the user's actual vision: browser-style tabs that show INSTANCES (specific runs, projects, materials), not collection categories. Collection pages are content WITHIN a tab, not tabs themselves. The splash page is a landing page for finding things to open as tabs.

**Architecture:** The core mistake was treating collection categories (Projects, Runs, Lab, Claims) as tabs. The user wants tabs to work like a browser: each tab shows one thing (a run, a project, a material), and navigating within a tab stays in that tab. The GlobalNavbar switches which collection page is shown in the CURRENT tab. The "+" button opens a splash page to find a new instance to open as a new tab.

**Tech Stack:** React, TypeScript, React Router, vitest

---

## Root Causes (from code review + browser review)

### Issue 1: Run view right pane takes full width
- `RunWorkspaceShell.tsx` passes `leftPane={children}` to AppShell but does NOT pass `rightPane`
- `RightPane` is rendered INSIDE the children (inside the left pane), not as the AppShell rightPane prop
- AppShell gives left pane 100% width when no rightPane is provided

### Issue 2: Tabs not unified (collection tabs redundant, run pages show zero tabs)
- GlobalNavbar opens "collection" tabs (Projects, Runs, Lab, Claims) — these are redundant with the top nav
- RunWorkspacePage uses its own RunWorkspaceShell which doesn't pass topbarTabs — no tab strip
- The user wants INSTANCE tabs (specific run, project, material), not category tabs

### Issue 3: Inline search/sort still visible
- CollectionSearchSort IS applied (confirmed by browser review — `.collection-search-sort__input` class is present)
- The user sees the search/sort bar but wants it REPLACED by a "universal control bar" — a single horizontal bar below the title that searches across entities AND relationships
- This is actually a feature request, not a bug — the CollectionSearchSort works but isn't the vision

## Revised Tab Architecture

### What should be a tab:
- A specific run (e.g. "RUN-first-run") — shows the event editor + right pane
- A specific project (e.g. "STU-my-project") — shows the project workspace
- A specific material/protocol/labware (e.g. "MAT-clofibrate") — shows the entity detail
- A collection page (e.g. "All Runs") — shows the searchable list
- A splash/landing page — the default tab when you click "+"

### What should NOT be a tab:
- "Projects" / "Runs" / "Lab" / "Claims" as persistent category tabs (redundant with GlobalNavbar)

### How navigation works:
1. **GlobalNavbar** (Projects/Runs/Lab/Claims) — switches the CONTENT of the current tab to show that collection page. Does NOT create a new tab. Just like clicking a bookmark in a browser.
2. **Tab strip** — shows all open tabs (instances + collection pages + splash). Clicking a tab switches to it. Closing a tab removes it.
3. **"+" button** — opens a splash page as a new tab. The splash page lets you search for anything and open it as a new tab.
4. **Clicking an item in a collection** (e.g. clicking a run in the Runs list) — opens that instance as a new tab and switches to it. Like clicking a link in a browser — it opens in a new tab, not the current one.

## Phase 2: Fix Tab Architecture

### Task 2.1: Stop GlobalNavbar from creating collection tabs

**Files:**
- Modify: `app/src/shared/shell/GlobalNavbar.tsx`

**Change:** Remove the `openTabs.openTab()` call from `handleDestination`. Just navigate — the route change will render the collection page in whatever tab is active:

```tsx
const handleDestination = (dest: { id: string; path: string; label: string }) => {
  navigate(dest.path)
}
```

This is the simplest fix. The GlobalNavbar switches the URL, which renders the collection page. No tab creation needed.

### Task 2.2: Remove WorkspaceTabStrip from standalone collection views

**Files:**
- Modify: `app/src/collections/ProjectCollectionView.tsx`
- Modify: `app/src/collections/RunCollectionView.tsx`
- Modify: `app/src/collections/LabCollectionView.tsx`

**Change:** In non-embedded mode, don't pass `topbarTabs={<WorkspaceTabStrip />}` to AppShell. Pass `topbarTabs={<div />}` (empty) or remove the prop entirely. The GlobalNavbar is the primary navigation on collection pages.

Actually, better: keep the WorkspaceTabStrip on collection pages so users can see their open instance tabs while browsing collections. But filter out collection-kind tabs from the strip so only instance tabs (run, project, lab-entity, claim) show.

### Task 2.3: Filter out collection tabs in WorkspaceTabStrip

**Files:**
- Modify: `app/src/shared/shell/WorkspaceTabStrip.tsx`

**Change:** Don't render tabs with `kind: 'collection'` in the strip:

```tsx
{state.tabs
  .filter(({ tab }) => tab.kind !== 'collection')
  .map(({ tab }) => {
    // ... existing rendering
  })}
```

This way the tab strip shows only instance tabs (runs, projects, materials, etc.), not the redundant "Projects" / "Runs" / "Lab" category tabs.

### Task 2.4: Open instance tabs when clicking items in collections

**Files:**
- Modify: `app/src/collections/ProjectCollectionView.tsx`
- Modify: `app/src/collections/RunCollectionView.tsx`
- Modify: `app/src/collections/LabCollectionView.tsx`

**Change:** When clicking a project card, open a project tab (not just navigate). When clicking a run, open a run tab. When clicking a lab entity, open a lab-entity tab.

```tsx
// In ProjectCollectionView, onClick of a project card:

```

Same pattern for RunCollectionView (open run tab) and LabCollectionView (open lab-entity tab).

## Risks

1. **RunWorkspaceShell layout** — Adding rightPane changes the panel split. Need to verify the event editor canvas still renders correctly in the narrower left pane.

2. **Tab lifecycle** — When should tabs be closed? Currently tabs persist in localStorage forever. Should there be a max tab limit?

3. **Splash page as tab** — The splash page needs a route. Currently there's no `/splash` route. Could use `/projects` as the default splash content, or create a dedicated route.

4. **Collection pages in tabs** — If the user clicks "Runs" in GlobalNavbar while on a run tab, what happens? The current tab's content changes to the Runs collection, but the tab still says "Run XXX". This is confusing. Either: (a) the tab title updates, or (b) GlobalNavbar opens a new collection tab (but we just said it shouldn't).

**Resolution for risk 4:** When GlobalNavbar switches to a collection page, it should REPLACE the current tab's content with the collection and update the tab title. This is like typing a URL in a browser tab — the tab stays the same but shows different content.
