## 6. Declarative-surface rules (binding; reviewer bait lives here)

1. **No policy in TS.** No analyte names, no unit literals, no RT/DREF ids, no saturation threshold,
   no `'min' | 'pA'` switches. Units, field names, labels and flag tokens come from artifact
   payloads or view-spec bindings.
2. **Bindings are the door.** New presentation knobs are optional binding keys (free-form per
   `view-spec.schema.yaml:50-59`) read by the renderer; revisions set them as DATA. No new renderer
   enum id (FAME-6 OQ-1 already minted the one generic id this campaign may add).
3. **No schema edits.** If a fix appears to need `schema/**`, STOP and report — the orchestrator
   re-rules (schema changes force a `:3092` restart and a registry review).
4. **No new local vocabulary.** `sampleName` and the marker binding names are existing/declared
   surfaces; do not mint a `sampleLabel` twin.
5. **exactOptionalPropertyTypes:** the app tsconfig enforces it. Optional props must be omitted, not
   passed as `undefined` — the FAME-7 spec and the existing `ChromatogramView` call sites show the
   correct `...(cond ? { k: v } : {})` shape. A `bindings={{ markerSaturatedField: undefined }}`
   style edit is a type error AND a review defect.
6. **No `as` laundering** of payloads to silence types; narrow with the existing `isRecord` helper.
